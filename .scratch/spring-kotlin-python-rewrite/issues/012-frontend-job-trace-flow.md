## Question

用低成本原型确定 React 单裁剪上传、颜色库选择、图纸级编码输入、任务进度轮询、历史状态筛选和只读追踪详情的最终交互；明确处理中/失败任务不展示半成品棋盘但仍能追溯的页面结构。

## Resolution

（由 `/prototype` subagent 制作，原型见 `prototypes/012-frontend-flow.html`，30/30 项 DOM 校验通过；以下为从原型确认的交互决议）

### 设计方向

"Pegboard system"：深色墨水 UI + 底板孔洞纹理，白色物理板面板承载图纸，3D 光泽豆粒（径向高光 + 内阴影）作为状态/图例/棋盘词汇；Bricolage Grotesque 标题 + Inter 正文 + JetBrains Mono 用于编码（编码即数据）。

### 上传页（单裁剪）

- 选文件只加载图像，**不自动识别**；"开始识别"按钮在图像 + 裁剪框 + 合法编码齐备前禁用。
- 裁剪框：图片上拖拽/缩放的矩形覆盖层（复用 CropBox 概念，单区域）。
- 行数/列数输入 1..500，实时显示单元格总数；编码输入为逗号分隔 chip 输入，逐条校验 `^[A-Za-z][0-9]{1,3}$`，失焦统一大写，非法 chip 红色 + 内联错误行。
- 提交模拟 `POST /api/v1/jobs` → 202 → 自动跳转追踪视图。

### 追踪视图（处理中/失败）

- 处理中**永不展示半成品棋盘**；追踪视图是替代呈现：进度条（百分比 + processed/total）、stage、attempt/retryCount、快照（model + colorLibraryVersion）、轮询说明（"React Query 每 2s 轮询 · 心跳每 30s"）、实时事件时间线（sequence、类型标签、payload、时间戳，覆盖 007 全部事件类型）。
- "查看图纸"按钮只在终态后出现；FAILED 显示错误横幅（code/message/重试次数），不显示棋盘、无图纸按钮。

### UNMAPPED 三处同词汇呈现

1. 追踪 + 图纸详情的警告横幅（`(row, col) + detail`）；2. 棋盘上独立斜纹 `?` 豆粒；3. 图例中独立 UNMAPPED 条目 + 悬停提示"⚠ 不在颜色库快照"。

### 历史页

- 状态筛选 chips（全部/PENDING/PROCESSING/SUCCEEDED/SUCCEEDED_WITH_WARNINGS/FAILED，各带实时计数）+ 分页（5/页）+ 行点击进入追踪视图；FAILED/警告状态在列表中保持可区分。

### 原型暴露的 4 个待定交互点（决议）

1. **轮询节奏**：固定 2s 轮询，不因长任务退避；丢失心跳不在前端呈现 stale（恢复由 Spring 侧完成），保持前端简单。
2. **图纸访问路径**：历史行只链到追踪视图，图纸经追踪视图"查看图纸"进入；SUCCEEDED 行不做直接深链（保持单一入口，后续可按反馈加）。
3. **编码输入与 422**：前端以 chip 形式逐个校验格式，格式问题在提交前拦截，不产生 API 调用；服务端 422 的字段级 details 按字段名映射回输入区显示，不做逐 chip 反向映射（非法格式在客户端已拦截，服务端 422 只应对边界情况）。
4. **警告坐标**：警告横幅始终显示 `(row, col)`；若坐标超出图案范围（不应发生），仍显示横幅，但无对应豆粒可标记。

### 页面结构

上传（单裁剪）/ 历史（筛选 + 分页）/ 追踪（只读，处理中替代棋盘）/ 图纸详情（终态只读棋盘 + 图例 + 警告）四页；追踪与图纸详情为任务的两段式呈现，共享同一任务上下文。
