# TRAINING — PART 2

**Updated:** 2026-08-01

This is **PART 2 of the repo layout** (`frontend/` / `server/` / `image_service/` / `ocr_core/` / `training/`). It owns:

- Synthetic dataset generation (`models/synth_generator.py`)
- Training, evaluation, and checkpoint-publishing scripts (`scripts/`)
- Real bead images and ground-truth annotations (`examples/` at repo root, `data/synthetic/`)
- Trained model checkpoints (`checkpoints/`)
- Published model artifacts (`artifacts/models/`, produced by `publish_checkpoint.py`)
- Training rationale (`docs/PLAN.md`)

The runtime CRNN architecture lives in the **shared `ocr_core/` package** (010 decision) — `training/` imports it; `image_service/` imports it. Neither imports the other, and neither touches the retired `backend/`.

## QUICKSTART

### Train a CRNN from scratch

```bash
# From repo root — `ocr_core` and `training.*` imports resolve via the package layout.
python -m training.scripts.train_crnn \
    --synth-n 50000 \
    --epochs 30 \
    --out training/checkpoints/crnn_v3.pt
```

Requires `torch` + `torchvision` (install separately; conda env `bead-train`).

### Evaluate / baseline

```bash
# Cell-level baseline + acceptance (011) — the number the new service must not regress below:
python -m training.scripts.eval_cell_baseline \
    --checkpoint training/checkpoints/crnn_real_m.pt --legacy \
    --json training/docs/baseline-check.json
# zip set exact_match = 0.7008 (5347/7630); acceptance: ≥ 0.7008 ± 0.005

# Grid-level eval (needs positioned GT):
python -m training.scripts.eval_stand
```

### Publish a checkpoint for runtime use

```bash
# Legacy 3-key checkpoints (no format_version) are migrated in memory:
python -m training.scripts.publish_checkpoint \
    --checkpoint training/checkpoints/crnn_real_m.pt \
    --name crnn_real_m --version 2026-08-01T00-00-00Z
# → artifacts/models/crnn_real_m-2026-08-01T00-00-00Z/{model.pt, charset.json, manifest.json}
# → artifacts/models/current → that dir

# Regenerate the color-library snapshot (source was retired backend/app/data/default_colors.json):
python -m training.scripts.publish_checkpoint --colors
```

`image_service/` loads the artifact via `MODEL_ARTIFACT_DIR` (default `artifacts/models/current`).

### Crop + annotate a new raw bead image

```bash
# 1. Drop the image into examples/ (repo root) or examples/stand/
# 2. Add a crop entry to training/scripts/crop_examples.py CROPS list
# 3. Run:
python -m training.scripts.crop_examples
# 4. Label cells with examples/stand/label.html; export marked cells + manifest.csv
```

## CONVENTIONS

- **Run scripts from the repo root** — `python -m training.scripts.X` so `ocr_core` and `training.*` both resolve.
- **Shared core is `ocr_core/`** (010): charset (`ocr_core.charset`), color codes (`ocr_core.code_library`, artifact snapshot), CRNN arch + checkpoint I/O (`ocr_core.bead_ocr_crnn`). `synth_generator.py` re-exports `CHARS`/`CHAR_TO_IDX` from `ocr_core.charset` for backward compatibility.
- **Checkpoint format (010 R2)**: `format_version=1` with `model_arch`, `num_classes`, `input_size`, `input_channels`, `blank_index`, `charset_hash` (hard checks at load) + `code_dict_version` (soft warn). Legacy 3-key checkpoints raise `CheckpointFormatError` — migrate via `publish_checkpoint.py`.
- **Real data lives in `examples/`** (repo root) — `samples/stand/` (1.jpg..3.jpg, cells/, cut/, manifest.json, 标注结果 zips), `examples/1.jpg..6.jpg`. The old `training/data/real/` + `training/data/annotations/` paths were retired with the backend (014).
- **Paths use `Path(__file__).resolve().parent.parent.parent`** to anchor at repo root, then navigate relative to it. Avoid `cwd`-relative paths.
- **Gitignore**: `training/checkpoints/*.pt`, `training/data/synthetic/`, `artifacts/models/**/model.pt` are ignored. `training/docs/` is excluded via `.git/info/exclude` on some checkouts — use `git add -f` for baseline docs if needed.

## ANTI-PATTERNS

- **`bead_ocr_vlm.py` is unreferenced** — experimental VLM path no script calls. Kept for future exploration. Delete if it stays unused.
- **`augment.py` is YOLO-specific** — the YOLO pipeline was removed; kept for historical reference.
- **`eval_stand.py` grid-level eval lacks positioned GT** — the annotation zips have codes but no row/col; grid-level acceptance is a follow-up (011 §5). Cell-level baseline is the current gate.
- **Legacy checkpoints are load-rejected by design** — don't patch `ocr_core.load_checkpoint` to accept them; use `publish_checkpoint.py --checkpoint ...` to migrate.

## NOTES

- The training plan (architecture choice, A/B benchmark history, why CRNN over VLM/template) lives in `training/docs/PLAN.md` — read that before changing the approach.
- Baseline model: `crnn_real_m.pt` — zip exact_match **0.7008**, ms/cell ~0.9-1.2 CPU. Acceptance rules in `training/docs/baseline-2026-07-31.md` (011).
- The CRNN's closed vocabulary derives from `ocr_core.charset` + the color-library snapshot (`artifacts/colors/library.json`, 65 codes, H/F/G). Adding a bead color requires updating the snapshot and re-training (or fine-tuning).
- Real bead images with Chinese filenames use UTF-8 — on Windows terminals you may see garbled output (the files themselves are fine).
