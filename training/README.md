# TRAINING — PART 2

**Updated:** 2026-07-26

This is **PART 2 of the three-part repo layout** (`frontend/` / `training/` / `backend/`). It owns:

- The CRNN model architecture (`models/bead_ocr_crnn.py`)
- Synthetic dataset generation (`models/synth_generator.py`)
- Training, evaluation, and data-prep scripts (`scripts/`)
- All real bead images and ground-truth annotations (`data/`, `crops/`)
- Trained model checkpoints (`checkpoints/`)
- Training rationale (`docs/PLAN.md`)

The backend (`backend/`) loads the trained `.pt` files from `training/checkpoints/` at runtime via `CRNN_MODEL_PATH` (default `"../training/checkpoints/crnn_v2.pt"` relative to `backend/app/`).

## QUICKSTART

### Train a CRNN from scratch

```bash
# From repo root — `training.*` imports resolve via the package layout.
python -m training.scripts.train_crnn \
    --synth-n 50000 \
    --epochs 30 \
    --out training/checkpoints/crnn_v3.pt
```

Requires `torch` + `torchvision` (install separately; not yet in `backend/environment.yml`).

### Evaluate a trained checkpoint

```bash
python -m training.scripts.eval_stand
# Override checkpoint:
CRNN_MODEL_PATH=../training/checkpoints/crnn_v3.pt python -m training.scripts.eval_stand
```

Reads `training/data/annotations/stand_manifest.json` and the corresponding `*.gt.json` files; prints per-image exact-match rate + overall.

### Use the trained model from the backend

The backend loads checkpoints lazily on first OCR call. To switch to a new checkpoint:

```bash
# Option 1: env var
export CRNN_MODEL_PATH=/abs/path/to/crnn_v3.pt
uvicorn app.main:app

# Option 2: edit backend/app/config.py default
# CRNN_MODEL_PATH: str = "../training/checkpoints/crnn_v3.pt"
```

Set `OCR_ENGINE=crnn` to actually use it (default is `easy`).

### Crop + annotate a new raw bead image

```bash
# 1. Drop the image into training/data/real/raw/
cp my_new_image.jpg training/data/real/raw/

# 2. Add a crop entry to training/scripts/crop_examples.py CROPS list
#    (specify source filename, output name, bbox, rows, cols)
# 3. Run:
python -m training.scripts.crop_examples

# 4. Open training/data/annotations/label_tool.html in a browser,
#    point it at the new cropped image, and label cells.
# 5. Export labels as GT JSON into training/data/annotations/stand_gt/
# 6. Update training/data/annotations/stand_manifest.json
```

## CONVENTIONS

- **Run scripts from the repo root** — `python -m training.scripts.X` so `training.*` and `backend.*` both resolve. Scripts add the repo root to `sys.path` defensively.
- **Cross-part imports are one-way**: training may import from `backend.*` (e.g. `backend.app.data.default_colors.json`), but `backend/*` only imports from `training.models.*` (the model architecture). The `training → backend` direction is for shared assets (color palette, runtime code loaders); the `backend → training` direction is for the trained model artifact.
- **Paths use `Path(__file__).resolve().parent.parent.parent`** to anchor at repo root, then navigate relative to it. Avoid `cwd`-relative paths.
- **Data is gitignored except for committed examples** — `training/data/synthetic/`, `training/checkpoints/*.pt` (except `crnn_v2.pt`) are gitignored; the real data and committed checkpoint are tracked.

## ANTI-PATTERNS

- **`bead_ocr_vlm.py` is unreferenced** — experimental VLM path that no script currently calls. Kept for future exploration. Delete if it stays unused.
- **`augment.py` is YOLO-specific** — the YOLO pipeline was removed; this script can no longer be used end-to-end. Kept for historical reference.
- **`build_gt_from_ocr.py` references a hardcoded image path** — `拼豆日记54...jpg` was removed from the repo in the 3-part refactor cleanup. Edit the script to point at your real image before running.
- **`synth_generator.py` resolves the color library via absolute path** — `Path(__file__).resolve().parent.parent.parent / "backend" / "app" / "data" / "default_colors.json"`. If you ever move `backend/`, update both `synth_generator.py` and `bead_ocr_vlm.py`.

## NOTES

- The training plan (architecture choice, A/B benchmark history, why CRNN over VLM/template) lives in `training/docs/PLAN.md` — read that before changing the approach.
- Real bead images with Chinese filenames (e.g. `拼豆日记...jpg`) use UTF-8 throughout — file paths work on Linux/macOS natively; on Windows you may see garbled output in some terminals (the files themselves are fine).
- Checkpoints are `.pt` files (PyTorch state dicts + metadata). Use `load_checkpoint(path)` from `training.models.bead_ocr_crnn` to read.
- The CRNN's closed vocabulary (CHARS, CODES) is derived from `backend/app/data/default_colors.json` at import time. Adding a new bead color to the library requires updating both the JSON and re-training (or fine-tuning) the CRNN.
